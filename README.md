# سنابل — نظام إدارة وتوزيع الطحين

هذا المستودع يحتوي تطبيق سنابل وملفات فحص الجودة والأمان الخاصة به.

## تشغيل التطبيق
التطبيق مبني حالياً كتطبيق ويب تقدمي (PWA) باستخدام HTML وCSS وJavaScript، وليس مشروع Android أصلياً أو APK.

- افتح `index.html` عبر خادم ويب محلي أو استضافة تدعم HTTPS.
- يمكن تثبيته كتطبيق من المتصفح عندما تكون الاستضافة مؤهلة لـ PWA.
- لا تعتمد على فتح الملف مباشرة من مدير الملفات لبعض الوظائف مثل Service Worker.

## فحوصات الجودة
تعمل GitHub Actions تلقائياً عند كل Push إلى `main)، وعند Pull Request، ويمكن تشغيلها يدوياً.

الفحوصات الحالية:
- التحقق من صياغة JavaScript وملفات HTML المضمنة.
- التحقق من وجود ملفات التطبيق والأيقونات والملفات المحلية المشار إليها.
- التحقق من صحة Web App Manifest ووجود أيقوناته.
- فحوصات تعاقدية لقواعد العمل الأساسية: 9 كغم لكل فرد، 250 ديناراً لكل فرد، وحجم الكيس 50 كغم.
- التحقق من صفحات العوائل والتوزيع والإحصائيات والإعدادات ومفاتيح التخزين.
- فحوصات تمنع رفع ملفات النسخ الاحتياطي الحساسة إلى المستودع.

لتشغيلها محلياً باستخدام Node.js 20 أو أحدث:
```bash
npm ci
npm run qa
npm run build
```

ملاحظة: أمر `npm run build` حالياً ينفذ فحوصات سلامة البناء والأصول، ولا ينشئ APK أو حزمة إنتاج مجمعة.

## فحص الأمان
- CodeQL يحلل JavaScript باستخدام مجموعة استعلامات `security-extended`.
- إعداد CodeQL الحالي ينفذ التحليل دون رفع SARIF لأن ميزة GitHub Code Scanning غير متاحة/غير مفعّلة لهذا المستودع. لذلك نجاح التحليل المحلي لا يعني ظهور تنبيهات في تبويب Security.
- Dependabot يراجع تحديثات GitHub Actions.
- راجع `SECURITY.md` قبل أي نشر أو تغيير أمني.

## مراقبة الأخطاء باستخدام Sentry
تم تضمين Sentry Browser Loader الخاص بمشروع Sentry في `index.html`، مع تهيئة في `sentry-init.js`.

إعدادات الخصوصية:
- `sendDefaultPii: false`.
- تعطيل breadcrumbs وPerformance Tracing وSession Replay.
- تنقية بيانات الحدث قبل الإرسال، وإزالة بيانات المستخدم والطلب والسياق والحقول الإضافية.
- عدم إرسال سجلات العوائل أو محتوى التخزين المحلي عمداً.

**حدود التحقق:** اختبارات GitHub تتحقق من وجود كود Sentry وإعدادات الخصوصية، لكنها لا تثبت وصول حدث فعلي إلى لوحة Sentry. يلزم تشغيل نسخة التطبيق من خادم ويب ثم إجراء اختبار مراقبة مقصود والتحقق من ظهوره في مشروع Sentry. لا تُرسل بيانات مستفيدين حقيقية أثناء الاختبار.

## حماية بيانات المستفيدين
- أبقِ المستودع خاصاً.
- لا ترفع ملفات النسخ الاحتياطي أو قواعد بيانات المستفيدين أو رموز Telegram.
- لا تضع أي بيانات شخصية في Issues أو سجلات CI أو Sentry.
- احتفظ بنسخة احتياطية مستقلة قبل تحديث التطبيق.
- QA يقلل احتمال الأخطاء لكنه لا يضمن خلو التطبيق منها بالكامل.

## الحالة
التطبيق وملفات الفحص موجودة في المستودع. نتيجة كل تشغيل موثوقة هي النتيجة الظاهرة في تبويب Actions؛ لا تعتبر أي فحص جارٍ ناجحاً حتى ينتهي بحالة `success`.
