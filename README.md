# سنابل — منظومة ضمان الجودة (QA)

مستودع خاص لإعداد منظومة ضمان الجودة والأمان لتطبيق **نظام إدارة وتوزيع الطحين — Flour Distribution Manager**.

## ما تم إعداده
- GitHub Actions لتشغيل الفحوصات عند كل Push وPull Request.
- اختبارات تراجعية لقواعد التطبيق الأساسية وصفحاته ونسخه الاحتياطية.
- CodeQL لتحليل JavaScript أمنياً.
- Dependabot لمراجعة تحديثات GitHub Actions.
- Dependency Review عند فتح Pull Request.
- قواعد حماية تمنع إضافة ملفات النسخ الاحتياطية والملفات السرية إلى Git.

## حالة المشروع الحالية
تم رفع ملفات منظومة QA إلى المستودع. **ملفات التطبيق الأصلية نفسها لم تُرفع بعد**؛ لذلك فحوصات التطبيق ستظهر كـ skipped إلى أن تضاف ملفات المشروع الأصلية (خصوصاً `index.html` و`src/app.js` و`sw.js` و`manifest.webmanifest`). لم أعدّل تصميم التطبيق أو قواعده.

## إعداد Sentry
1. أنشئ مشروعاً من نوع JavaScript في Sentry.
2. انسخ DSN الخاص بالمشروع.
3. في GitHub افتح Settings → Secrets and variables → Actions.
4. أضف Repository Secret باسم `SENTRY_DSN` وضع قيمة DSN.
5. أبلغني عند إضافته حتى أدمج SDK في التطبيق مع تنقية بيانات المستفيدين.

**مهم:** إضافة السر وحدها لا تفعّل مراقبة المتصفح؛ يلزم ربط SDK بملفات التطبيق بعد رفعها. لا تضع Telegram Bot Token أو بيانات العوائل في Sentry أو GitHub.

## تشغيل الفحوصات محلياً
يتطلب Node.js 20 أو أحدث:
```bash
npm run qa
```

## حماية البيانات
- أبقِ المستودع Private.
- لا ترفع ملفات النسخ الاحتياطي أو بيانات المستفيدين.
- لا ترفع رموز Telegram أو روابط تكامل خاصة.
- راجع [SECURITY.md](SECURITY.md).

## حدود الضمان
QA يقلل الأخطاء ويكشف الانحدارات مبكراً، لكنه لا يضمن انعدام الأخطاء تماماً. اختبر دائماً نسخة احتياطية قبل التحديثات الكبيرة.
