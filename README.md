# سنابل — نظام إدارة وتوزيع الطحين

تطبيق عربي RTL لإدارة العوائل وحصص الطحين والتوزيع الشهري، مع سجل محلي للأخطاء ومراقبة اختيارية عبر Sentry.

## البنية الحالية
- `index.html`: واجهة التطبيق والمنطق الرئيسي.
- `manifest.webmanifest`, `sw.js`, `icon-*.png`, `icon.svg`: ملفات PWA.
- `scripts/`: الفحص والبناء وتجهيز نسخة Android.
- `tests/`: اختبارات الوحدة واختبارات المتصفح.
- `qa/`: فحوصات عقد التطبيق والمراجعة الثابتة.
- `.github/workflows/`: اختبارات الجودة، فحص CodeQL، وبناء APK.

## Quality Assurance
عند كل Push إلى `main` أو فرع `qa/**`، وعند فتح Pull Request إلى `main`، يعمل GitHub Actions على:
1. فحص صياغة JavaScript وملفات التطبيق المطلوبة.
2. تشغيل اختبارات الوحدة واختبارات التراجع.
3. إنشاء نسخة إنتاجية في `dist/` ورفعها كـ Artifact.
4. تشغيل اختبارات المتصفح باستخدام Playwright.
5. فحص أمني للكود باستخدام CodeQL.

شغّل محلياً: `npm install` ثم `npm run verify`. واختبار المتصفح: `npx playwright install chromium` ثم `npm run e2e`.

## بناء Android
يتطلب Node.js وJava 21 وAndroid SDK:
- `npm run qa`
- `npm run build:web`
- `npx cap add android` (مرة واحدة في بيئة البناء)
- `npm run build:android`

يُنتج GitHub Actions ملف APK كـ Artifact عند نجاح البناء.

## مراقبة الأخطاء — Sentry
1. أنشئ مشروعاً من نوع Browser JavaScript في Sentry.
2. انسخ DSN وأدخله داخل التطبيق: الإعدادات ← مراقبة الأخطاء ← حفظ.
3. استخدم زر «خطأ تجريبي» وتحقق من وصول الحدث إلى Sentry.
4. فعّل تنبيه New Issue في لوحة Sentry لاكتشاف الأخطاء مبكراً.

**الخصوصية:** Sentry غير مفعّل حتى يضيف المستخدم DSN. قبل إرسال الحدث، تُحذف بيانات المستخدم والطلب والسياق والمسارات الحساسة، وتُخفى رسالة الخطأ. لا تُرسل أسماء العوائل أو أرقام الهواتف أو العناوين أو سجلات التوزيع إلى Sentry. رمز القراءة الخاص بجلب المشكلات من Sentry يُحفظ محلياً على الجهاز ولا يُرفع إلى GitHub.

## النشر الآمن
كل العمل الحالي على فرع `qa/integrate-sanabil-app6` وPull Request رقم 5. لا تدمج إلى `main` إلا بعد نجاح جميع الفحوصات ومراجعة أي فشل. لا ترفع ملفات النسخ الاحتياطية أو بيانات المستفيدين إلى المستودع.
